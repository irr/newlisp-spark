newLISP Spark v.10.8 Stable Release 2026-09-19

This release reimplements the HTTP client on top of libcurl using the libffi-based FFI. The built-in C HTTP client was removed; all HTTP requests are now made by pure newLISP code in modules/curl.lsp.

Changes

  • get-url, put-url, post-url and delete-url are no longer C primitives. They are implemented in modules/curl.lsp (libcurl via FFI) and become available after (module "curl.lsp"). Requires a libffi-enabled build (-DFFI, the default) and a Linux shared libcurl library.
  • URL support in load, save, read-file, write-file, append-file and delete-file now delegates to the curl module. Without (module "curl.lsp") loaded, these functions fail on http:// URLs as if the file could not be accessed.
  • The built-in HTTP server (newlisp -http -d port) and base64-enc/base64-dec remain implemented in C and are unchanged.
  • modules/xmlrpc-client.lsp loads the curl module automatically.

New Features

  • https:// URLs are now supported by the HTTP client (the legacy client only spoke plain HTTP).

Compatibility with previous versions

The four *-url functions keep their classic names, signatures, options ("header", "list", "debug", "raw"), timeouts, custom headers, HTTP_PROXY support, file:// handling and ERR: message strings. xfer-event handlers are called for each block of data received. Scripts only need to add (module "curl.lsp"). The module can also be loaded on older binaries (10.7.6 and earlier), where it detects the built-in C primitives and leaves them untouched. Otherwise compatible with the previous versions in the 10.x series.
